# VibeCoding 基准项目

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

为所有 VibeCoding（AI 辅助开发）项目提供统一规范、约束与任务模板的基准仓库。所有派生项目以此为基线，**可加严、不得放宽**。

## 目录结构

| 路径 | 内容 |
|---|---|
| `AGENTS.md` | AI 协作约定（AI 执行任务的第一读文件） |
| `GLOSSARY.md` | 项目术语表（共享语言，依据总纲第 8 条第 4 款） |
| `specs/` | 规范：总纲 + 角色规范 |
| `templates/` | 任务模板：受理 / 设计 / 测试用例 / 测试报告 / 评审 / 会话交接 / 术语表 |
| `LICENSE` | MIT 开源许可（© 2026 lplulu@foxmail.com） |
| `.gitignore` | 版本库忽略规则（机密 / 构建产物 / 环境文件） |

|---|---|---|---|

## 快速开始（发起一个任务）

1. 用 `templates/任务受理模板.md` 填写任务：目标、验收标准（必须可检查）、范围边界、工作方式（单步 / 全自动，未指定默认单步）。
2. 工程师按六步闭环执行：澄清 → 探查 → 文档确认 → 编码 → 自测 → 交付（**先确认文档再编码**）；设计阶段同步维护 `GLOSSARY.md` 术语表。
3. 移交高级测试工程师（VCS-QA-001）执行独立测试与版本质量评估，输出测试用例与 `templates/测试报告模板.md`；**工程师自测不替代独立测试**。
4. 交付前逐项通过质量门（见总纲第 5 节），并按工程师规范完成自我检查清单。
5. 需要时由评审员按 VCS-REV-001 独立评审（只看不改），输出 `templates/评审报告模板.md` 格式的评审报告。
6. 会话结束：更新 `templates/会话交接模板.md`，供下一轮对话快速承接。

## 派生与同步

- **继承方式**：派生项目复制本仓库 `specs/` 与 `templates/` 作为基线（或 fork 后清理示例内容），并在自身 `AGENTS.md` 中声明所继承的规范版本。
- **只许加严**：可新增条款、提高门槛（如更细的提交粒度、更多的评审维度），不得删除或放宽既有 MUST / MUST NOT 条款。
- **上游同步**：上游规范升级后，派生项目须评估差异并在下一次版本变更中合并；暂不跟进的，须在自身版本记录中注明滞后版本与原因。
- **术语继承**：派生项目 `GLOSSARY.md` 在继承上游术语的基础上追加领域术语，不得与上游定义冲突。

## 规范演进

修改任何规范需经评审并升级版本号，变更记录写入各规范内的版本记录表。下游项目只许加严、不得放宽。
