# VibeCoding 基准项目

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

为所有 VibeCoding（AI 辅助开发）项目提供统一规范、约束与任务模板的基准仓库。所有派生项目以此为基线，**可加严、不得放宽**。

## 目录结构

| 路径 | 内容 |
|---|---|
| `AGENTS.md` | AI 协作约定（AI 执行任务的第一读文件） |
| `GLOSSARY.md` | 项目术语表（共享语言，依据总纲第 8 条第 4 款） |
| `specs/` | 规范：总纲 + 角色规范 |
| `templates/` | 任务模板：受理 / 设计 / 测试 / 评审 / 会话交接 / 术语表 |
| `LICENSE` | MIT 开源许可（© 2026 lplulu@foxmail.com） |
| `.gitignore` | 版本库忽略规则（机密 / 构建产物 / 环境文件） |

## 规范清单

|---|---|---|---|
| VCS-WF-001 | VibeCoding 工作流约束规范（总纲） | v0.3 | 正式 |
| VCS-ENG-001 | 高级开发工程师工作规范 | v0.3 | 正式 |
| VCS-REV-001 | 高级项目评审员工作规范 | v0.3 | 正式 |

## 快速开始（发起一个任务）

1. 用 `templates/任务受理模板.md` 填写任务：目标、验收标准（必须可检查）、范围边界、工作方式（单步 / 全自动，未指定默认单步）。
2. 工程师按六步闭环执行：澄清 → 探查 → 文档确认 → 编码 → 自测 → 交付（**先确认文档再编码**）。
3. 交付前逐项通过质量门（见总纲第 5 节），并按工程师规范完成自我检查清单。
4. 需要时由评审员按 VCS-REV-001 独立评审（只看不改），输出 `templates/评审报告模板.md` 格式的评审报告。
5. 会话结束：更新 `templates/会话交接模板.md`，供下一轮对话快速承接。

## 规范演进

修改任何规范需经评审并升级版本号，变更记录写入各规范内的版本记录表。下游项目只许加严、不得放宽。
